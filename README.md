# EchoVision — эхолокация вместо зрения (Fabric, Minecraft 26.2)

## Что делает мод
- Экран полностью чёрный — игрок визуально слеп. Стандартный прицел (+)
  при этом остаётся на месте, как обычно.
- Каждый игровой звук (шаги, мобы, взрывы, двери, дождь и т.д.) вместо
  того чтобы просто проиграться, порождает волну эха, которая по-настоящему
  распространяется в 3D-мире от точки звука: трассировкой лучей
  (`EchoRayTracer`, через `level.clip(...)`) находятся ближайшие
  поверхности вокруг источника, и по мере того как волна до них "долетает",
  они на мгновение проявляются на экране — причём именно там, где они
  реально находятся с точки зрения текущей позиции и поворота камеры
  игрока (не как плоская мини-карта, а как настоящая 3D-проекция), и
  текстурой того самого блока, от которого отразилась волна.
- Если включить микрофон (клавиша `;` по умолчанию), реальные звуки вокруг
  тебя (голос, хлопок, стук) точно так же расходятся волной в 3D — только
  источник этой волны не какой-то блок, а сам игрок.
- Клавиша `'` включает/выключает режим слепоты+эха целиком.

## Почему раньше "работал только микрофон" и была нагрузка на ПК
Микрофон читал буферы примерно раз в ~20 мс и на каждый такой буфер слал
отдельную волну — 40+ волн в секунду. Короткий список активных волн
мгновенно забивался микрофонными волнами, вытесняя редкие волны от звуков
мира, а сама частота создания волн (а не отрисовка) и была основной
нагрузкой. Сейчас `MicrophoneCapture` собирает пиковую громкость за окно
~150 мс и шлёт не чаще одного импульса за это время, а `SoundPulseManager`
дополнительно ограничивает, сколько волн можно оттрассировать за один тик
(`MAX_TRACES_PER_TICK` / `MAX_RAYS_PER_TICK`), так что даже пачка звуков
одновременно не даёт просадок кадров — она просто чуть растягивается по
времени. Настоящая система частиц движка (`Particle`/`ParticleEngine`)
нигде не используется — только лёгкие POJO-объекты.

## Важно про приватность
Звук с микрофона нигде не сохраняется и никуда не отправляется — из
каждого маленького буфера сразу считается громкость (одно число), а сами
сэмплы сразу выбрасываются. Захват стартует только когда ты сам включишь
его клавишей, и полностью останавливается по выключению
(`MicrophoneCapture.stop()` закрывает линию).

## ВАЖНО: почему билд ломался и что изменилось
Начиная с Minecraft 26.1 Mojang публикует джарники клиента/сервера уже
**без обфускации**. Из-за этого:

- Yarn-мэппинги для новых версий больше не публикуются вообще —
  `net.fabricmc:yarn:26.2+build.1` не существует.
- Официальные мэппинги Mojang для таких версий **тоже не публикуются** —
  маппить попросту нечего, код и так с настоящими именами. Поэтому в
  `dependencies {}` нет и не должно быть строки `mappings ...` вообще.
- Fabric завёл отдельный плагин с полным именем `net.fabricmc.fabric-loom`
  специально для необфусцированных версий — он ничего не ремаппит.
  Короткий `fabric-loom` (без `net.fabricmc.`) — это legacy-вариант
  только для старых обфусцированных версий, он тут не подходит.
- Раз ремаппинга нет, обычные `modImplementation`/`modCompileOnly`
  заменяются на стандартные Gradle-конфигурации `implementation`/
  `compileOnly`, а `remapJar` — на обычный `jar` (у нас он и так `jar`).

Источник: официальный пост Fabric про 26.1 —
https://fabricmc.net/2026/03/14/261.html

Отсюда же следует, что все имена классов в коде — это уже официальные
имена Mojang (`Minecraft`, `LocalPlayer`, `GuiGraphics`, `KeyMapping`,
`Component`, `net.minecraft.client.sounds.SoundManager` и т.д.), а не
старые Yarn-имена (`MinecraftClient`, `ClientPlayerEntity`, `DrawContext`,
`KeyBinding`, `Text`). Всё это я уже поправил в коде.

## Сборка
1. Открой `gradle.properties` и при необходимости проверь актуальные
   `loom_version` / `loader_version` / `fabric_version` для Minecraft 26.2
   на https://fabricmc.net/develop/ — 26.2 очень свежая версия, номера
   могли уже поменяться после написания этого мода (06.08.2026).
   Официально рекомендованы: Loom 1.17, Gradle 9.5.1, Fabric Loader 0.19.3.
2. `./gradlew build` (или через IntelliJ IDEA — Import Gradle Project).
3. Готовый jar появится в `build/libs/`.
4. Закинь его в `.minecraft/mods` вместе с Fabric API той же версии
   (сама игра тоже должна быть 26.2 + Fabric Loader).

## Если мод всё ещё не компилируется
- `loom_version=1.17-SNAPSHOT` — я не могу гарантированно проверить точный
  номер релиза Loom из этой песочницы (нет доступа в интернет при сборке).
  Если Gradle не найдёт такую версию плагина, зайди на
  https://fabricmc.net/develop/, выбери 26.2 и скопируй точный
  `loom_version` оттуда.
- `SoundManagerMixin` целится в метод `play(SoundInstance)` класса
  `net.minecraft.client.sounds.SoundManager`. Если в 26.2 сигнатура вдруг
  изменилась, запусти `./gradlew genSources` и открой декомпилированный
  `SoundManager.java`, чтобы свериться с актуальным именем метода.

## Что можно докрутить
- Разные цвета отметок для разных категорий звука (`SoundSource`) —
  например, шаги мобов одним цветом, взрывы — другим (сейчас всего два
  цвета: мир/микрофон).
- Частотный анализ микрофона (FFT) вместо простой громкости — тогда можно
  делать волны разного цвета в зависимости от высоты звука.
- Отдельный конфиг-файл для чувствительности микрофона, дальности эха
  (`SoundPulseManager.MAX_ECHO_DISTANCE`) и бюджета лучей на тик вместо
  хардкода констант.
- `EchoVisionHud#projectAndDraw` использует предположительный метод блита
  спрайта с тинтом (`context.blitSprite(...)`) — сверьте сигнатуру с
  реальным `GuiGraphicsExtractor`/`GuiGraphics` вашей версии, этот
  интерфейс не входил в присланные файлы, поэтому точно проверить его API
  здесь было нельзя.
